# T1 Investigation — Hypothesis H1 (Hook Anchor, Background Check & Dual-Channel Chat Reminder on Antigravity)

## 1. SessionStart & PreInvocation Runtime Execution Path on Antigravity

- **[Verified]** `scripts/tdq_hook_launcher.mjs` does **not** exist at repo root; the active launcher is `plugins/tdq-workflow-agy/scripts/tdq_hook_launcher.mjs`.
  - `plugins/tdq-workflow-agy/hooks.json:4-8, 13-17`: Both `SessionStart` and `PreInvocation` run `node scripts/tdq_hook_launcher.mjs --event <Event>`.
  - `plugins/tdq-workflow-agy/scripts/tdq_hook_launcher.mjs:7-12, 98-119`: Node resolves OS/arch binary (`win32:x64` → `bin/tdq-dispatch.exe`), executes it synchronously (`spawnSync`), and falls back to Python `hooks/scripts/dispatch.py` only if the Rust binary is missing/fails.
  - `hooks/rust/tdq-dispatch/src/main.rs:328-331, 400-410`: Although `hooks/rust/tdq-dispatch/src/events/session_start.rs:10-62` implements a pure-Rust `handle_session_start()`, `route_event()` at `main.rs:330` explicitly returns `RouteOutcome::DelegatePython` for `"SessionStart"`. Thus `SessionStart` on Antigravity runs **Node launcher → Rust `tdq-dispatch` → Python `dispatch.py` (`session_start.py`)** (cold-path, every session).
  - `hooks/rust/tdq-dispatch/src/events/pre_invocation.rs:188-239`: `PreInvocation` is a hybrid router:
    - Subagents and mid-turn tool invocations (`!meta.turn_closed && sig == meta.last_user_sig && !state_newer_than_meta`) resolve in Rust hot-path (`RouteOutcome::Decided`).
    - New user turns (`meta.turn_closed`, missing `turn-meta`, changed `last_user_sig`, `state_newer_than_meta`, `setup_pending`, or `source` in `resume`/`compact`) return `RouteOutcome::DelegatePython`, invoking Python `hooks/scripts/prompt_context.py`.

## 2. Hot-Path Budget & Detached Background Check Feasibility

- **[Verified]** `hooks/rust/tdq-dispatch/src/lib.rs:10-20` & `main.rs:345-356` & `tests/test_investigate_workflow.py:388`: Rust hot-path keeps `< 50 ms` latency (benchmarked `<= 25 ms` for ranged-read hot-direct) by avoiding Python subprocesses on mid-turn `PreToolUse`/`PreInvocation`/`PostInvocation` calls.
- **[Verified]** `SessionStart` already pays Python cold-path cost (`main.rs:330`), and `hooks/scripts/session_start.py:155-187` (`kich_hoat_nen`) already demonstrates spawning detached background Python workers (`DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP | CREATE_NO_WINDOW` on Windows, `start_new_session=True` on POSIX, `DEVNULL` stdio, `close_fds=True`, plus stamp-file debouncing `DAU_DA_GOI`/`CUA_SO_DA_GOI_GIAY`).
- **[Inferred]** Triggering a detached background remote check from Python `SessionStart` (`session_start.py`) or new-turn Python `PreInvocation` (`prompt_context.py`) adds negligible latency (< few ms `Popen`) and avoids blocking the `< 50 ms` Rust hot-path. If triggered inside Rust hot-path (`pre_invocation.rs`), spawning a detached process would still be non-blocking, but new-turn `PreInvocation` already delegates to Python anyway and `SessionStart` already runs Python.

## 3. Why `kich_hoat_kiem_tra_remote_nen()` Is Gated While `doc_thong_bao_update_moi()` Is Not

- **[Verified]** In `hooks/scripts/session_start.py:229-247` (and identically in `plugins/tdq-workflow-agy/hooks/scripts/session_start.py`, confirmed by `difflib` against `hooks/scripts/session_start.py`):
  - `tu_dong_cap_nhat_plugin_user(...)` (`230-236`) is gated by `if not is_agy():`.
  - `doc_thong_bao_update_moi()` (`237-241`) is **NOT** gated (`if not is_agy():` absent) — it reads the local notice file and appends to `nhac` (`333-335`).
  - `kich_hoat_kiem_tra_remote_nen()` (`242-246`) **IS** gated by `if not is_agy():`.
- **[Inferred]** Because `kich_hoat_kiem_tra_remote_nen()` is skipped when `is_agy()` is True, on pure-Antigravity machines nothing ever triggers the background remote update probe, leaving `doc_thong_bao_update_moi()` dormant unless a non-AGY session or manual `tdq_setup.py` run populated the local notice file. (Exact body of `tdq_setup.kich_hoat_kiem_tra_remote_nen` was not read — see Gaps.)
- **[Verified]** Additionally, `session_start.py` only calls `emit_context(...)` (`session_start.py:25, 400+`) and never calls `emit_user_markdown(...)`, so `thong_bao_update_nen` in `SessionStart` reaches the model (`systemMessage`) only, not `metadata.user_markdown`.

## 4. Antigravity Dual-Channel Rendering (`injectSteps` vs `user_markdown`)

- **[Verified]** `hooks/rust/tdq-dispatch/src/protocol.rs:74-108, 149-178, 721-726` and `tools/patches/agy_hooks.py:481-505, 533-555, 755-774`:
  - For `SessionStart`, `PreInvocation`, and `PostInvocation`, Antigravity 2.0 expects:
    `{"injectSteps": [{"systemMessage": {"systemMessage": "<AI model text>", "metadata": {"user_markdown": "<user chat card>"}}}]}`
    (Note: `additionalContext` is legacy-only at `agy_hooks.py:529`, omitted in AGY `injectSteps` per `protocol.rs:725`).
  - **AI channel:** `systemMessage.systemMessage` via Python `emit_context(...)` (`agy_hooks.py:755-764`) or Rust `HookDecision::inject(model_text, ...)` (`protocol.rs:150`).
  - **Direct user chat channel:** `systemMessage.metadata.user_markdown` (capped at `MAX_USER_MARKDOWN_CHARS = 1200` in `protocol.rs:11` and `agy_hooks.py:65`) via Python `emit_user_markdown(...)` (`agy_hooks.py:767-774`) or Rust `HookDecision::inject(..., Some(user_md))`.
  - **Dual-channel queue:** `queue_remind()` / `flush_pending_channels()` (`agy_hooks.py:809-868`) and `GuidanceRepo::merge_pending_channels()` (`protocol.rs:658-690`) support queuing both `model_line` (`<= 160`, summary `<= 200`) and `user_card` (`<= 1200`) across hooks.
  - **Setup hook pattern:** `hooks/scripts/prompt_context.py:221-230` (`_emit_setup_hooks`) supports emitting to both `emit_context([final_line])` and `user_md_fn(final_line)` (note: `hooks/scripts/prompt_context.py:439` passes `user_md_fn=None` in the unpatched copy, while `tests/test_hook_setup_resume.py:233, 281-285` tests `user_markdown` emission in compiled AGY `PreInvocation`).

## 5. 23-Code AGY Parity Contract Impact (`[TDQ:UPDATE]` vs `[TDQ:SETUP]` / Non-Code / `[TDQ:REMIND]`)

- **[Verified]** Adding a new `[TDQ:UPDATE]` (or `[TDQ:REMIND]`) code to `AGY_CODES` / `gate_guidance.json` **breaks** strict 23-code parity checks across:
  - `tools/patches/agy_hooks.py:36-61` (`AGY_CODES` tuple = 23 codes; neither `UPDATE` nor `REMIND` exists).
  - `tests/test_hooks_dual_protocol.py:28, 72-76` (`assert len(_common.CODES) == 23`, `EXPECTED_23_CODES`).
  - `tests/test_gate_guidance.py:55, 73-75, 113-114` (`assert len(ALL_AGY_CODES) == 23`, `assert len(raw["all_agy_codes"]) == 23`).
  - `tests/test_investigate_workflow.py:417-418` (`assert len(guidance["guidance_codes"]) == 23`).
  - `tests/test_rust_dispatch_parity.py:47-54, 697-707` (`assert len(codes) == 23`, `test_matrix_covers_all_23_agy_codes_and_6_events`).
- **[Verified]** Reusing **`[TDQ:SETUP]`** preserves the 23-code parity contract AND gives full `GuidanceRepo` / `gate_guidance.json` 4-part `user_markdown` support (`protocol.rs:608-656`, `agy_hooks.py:776-806`). Alternatively, emitting a non-code `[TDQ]` prefix (like `session_start.py:343`) or unregistered ad-hoc prefix (like `prompt_context.py:410` `[TDQ:FEEDBACK]`) directly to `emit_context` + `emit_user_markdown` also avoids touching `AGY_CODES`, though `GuidanceRepo::format_4part_card` falls back to `**[TDQ:<CODE>]**: <detail>` when a code is absent from `gate_guidance.json` (`protocol.rs:624-628`).
