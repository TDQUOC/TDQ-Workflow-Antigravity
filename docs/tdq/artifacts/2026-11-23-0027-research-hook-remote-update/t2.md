## 3. Comparison of 3 Remote Version-Checking Mechanisms

| Dimension | Option A: `git ls-remote` SHA only | Option B: Raw file / GitHub API | Option C: Two-Step Hybrid + Async TTL (Recommended) |
|---|---|---|---|
| **Mechanism** | `git ls-remote --heads <repo> <branch>` compared vs stored SHA | Fetch `raw.githubusercontent.com/.../plugin.json` or `api.github.com` | 1) TTL/opt-out check on disk; 2) Detached `git ls-remote` SHA check; 3) Fetch `plugin.json` only on SHA delta |
| **Hot-path hook cost** | ~700 ms if synchronous (blocks `SessionStart`) | ~365–426 ms if synchronous | **< 1 ms** (reads cached stamp synchronously; network runs detached via `Popen`) |
| **Rate limits** | None (Git smart HTTP/SSH `upload-pack`) | `api.github.com`: 60 req/hr unauth; `raw.githubusercontent.com`: no JSON API quota (~5m CDN cache) | Minimal: `ls-remote` hits Git transport (no 60/hr API cap); raw fetch fires **only when SHA changes** |
| **Semver vs commit noise** | False positives on non-version commits; no initial SHA in non-git install dir | Exact semver compare (`tach_version`), but needs fallback path across `release/antigravity` vs `dev`/`main` | Exact semver compare via `plugin.json` (`/` fallback `plugins/tdq-workflow-agy/plugin.json`) gated by SHA delta |
| **Private repos** | Uses local `git` credential helper / SSH; **must** set `GIT_TERMINAL_PROMPT=0` + 3–5s timeout to prevent hang | `raw.githubusercontent.com` returns **404** without `GITHUB_TOKEN` | Inherits `git` SSH/credential helper safely with `GIT_TERMINAL_PROMPT=0` + timeout; raw fetch falls back/fails silently |
| **Offline / timeout behavior** | Fails fast with timeout if configured; otherwise retries every hook without stamp | Same unless cached | Records `last_check` + `last_error` in stamp on failure so offline hooks stay silent for full TTL |
| **Branch flexibility** | High (`<branch>` passed directly) | Medium (path differs between compiled vs source branches) | High: configurable repo/branch (`release/antigravity` default) + path probe (`plugin.json` then `plugins/tdq-workflow-agy/plugin.json`) |

### Verdict for H2
- **Falsified assumptions:**
  1. `plugins/tdq-workflow-agy/plugin.json` is NOT present on `release/antigravity` (returns HTTP 404); `plugin.json` lives at branch root (`HTTP 200` in 426 ms).
  2. Existing `scripts/tdq_setup.py:919-966` remote update code cannot be reused as-is for Antigravity because it invokes `claude plugin marketplace update` and looks for `.claude-plugin/plugin.json`.
  3. Synchronous network checks (365–700 ms) inside `SessionStart` / `PreInvocation` hooks violate low-latency hook budgets and risk hanging offline or on private-repo credential prompts.
- **Confirmed viable design (Option C):** Detached background check triggered from `SessionStart` (`kich_hoat_kiem_tra_remote_nen` pattern), guarded by `TDQ_AUTO_UPDATE=0`, TTL (`6–24h` via `TDQ_UPDATE_INTERVAL_SECONDS`), and `dismissed_version` snooze. Uses `git ls-remote --heads` with `GIT_TERMINAL_PROMPT=0` + 4s timeout as cheap SHA gate, fetches `plugin.json` (`/` then `plugins/tdq-workflow-agy/plugin.json`) only on SHA mismatch, caches result in `${PLUGIN_DATA}/update-stamp.json`, and prints a single concise update notice (plus the exact `agy plugin install ...` command) on the next session start.
