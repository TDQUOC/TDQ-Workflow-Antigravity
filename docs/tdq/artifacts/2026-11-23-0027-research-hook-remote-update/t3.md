# T3 Investigation: H3 & H4 — Consent Trigger, Windows Overwrite, Locking, State & `--setupfully` Chain

## Summary

- **H3 (`prompt_context.py` consent guard)**: Viable and already hardened against prompt injection/accidental triggers via `_tach_prompt_thuc`, `_has_prompt_grant_blockers`, question/quote rejection, and `effective_new` turn filtering (`hooks/scripts/prompt_context.py:169-231`). Missing piece for update prompts: an anti-spam snooze/dismiss state in `${PLUGIN_DATA}`.
- **H4 (Windows overwrite, locking, backup, Caveman & `--setupfully` chain)**:
  - `README-Antigravity.md:10,16` documents `agy plugin install https://github.com/.../tree/release/antigravity`, **but** live `agy.exe plugin` CLI help says `install <target> (supports plugin[@marketplace])` and `agy plugin install --help` fails with `Error: install target must be a directory: --help`.
  - Persistent state (`setup-state.json`, `secrets.env`, `setup-pending.flag`) and `backups/` live in `${PLUGIN_DATA}` (`~/.gemini/antigravity/plugin_data/tdq-workflow-agy/`), completely outside `~/.gemini/config/plugins/tdq-workflow-agy/`, so plugin overwrite preserves them.
  - `tools/patches/common_utils.py:45-82` (`sync_tree_inplace`) overwrites files in-place with `shutil.copy2` instead of `rmtree` on the root dir. Short-lived `bin/tdq-dispatch.exe` had 0 running processes during probe, **but** any running `.exe` (`agent-lsp.exe` or an active `tdq-dispatch.exe` parent/concurrent hook) causes Windows PE write-lock failure (`WinError 5/32`) unless stopped/staged via `.tmp` + `os.replace` or skipped when unchanged.
  - Chaining `backup -> overwrite -> tdq_setup.py --setupfully -> awaiting_restart -> Antigravity restart -> --post-restart-verify` works end-to-end via `compute_host_session_fingerprint` and `evaluate_restart_resume`.

## Verified Findings

### 1. `agy plugin` CLI Reality vs `README-Antigravity.md`

- `agy plugin --help`: lists `install <target>       Install a plugin (supports plugin[@marketplace])`.
- `agy plugin install --help`: exits with `Error: install target must be a directory: --help`.
- `agy plugin list --json`: reports `"name": "tdq-workflow-agy"`, `"enabled": true`, `"version": "0.105.0"`, `"path": "C:\\Users\\admin\\.gemini\\config\\plugins\\tdq-workflow-agy"` (no `"source"` marketplace field, unlike official plugins with `"source": "antigravity-plugins-official"`).
- `README-Antigravity.md:10,16`: instructs users to run `agy plugin install https://github.com/TDQUOC/TDQ-Workflow-Antigravity/tree/release/antigravity` for initial install and updates.
- **Gap**: Did not execute `agy plugin install <url>` to avoid mutating live `~/.gemini/config/plugins/`. Because `agy plugin install` errors `install target must be a directory` on non-dir arguments and `--help` lists only `plugin[@marketplace]`, a remote updater cannot rely blindly on passing a GitHub URL to `agy plugin install` without verifying or downloading to a local staging directory and syncing/installing from disk.

### 2. Live Plugin Directory, State Separation & Windows File Locking

- `~/.gemini/config/plugins/tdq-workflow-agy/` contains: `agents/`, `assets/`, `bin/` (`tdq-dispatch.exe` 2,022,912B, `tdq-dispatch-darwin-arm64`, `tdq-dispatch-linux-x86_64`), `docs/`, `hooks/`, `rules/`, `scripts/`, `skills/`, `hooks.json`, `manifest.json`, `mcp_config.json`, `mcp_config.json.bak`, `plugin.json`, `README.md`, `tdq-config.json`.
- `~/.gemini/antigravity/plugin_data/tdq-workflow-agy/` contains: `backups/`, `logs/`, `setup-state.json` (7,391B).
- `tools/install_agy_plugin.py:148-190` (`_resolve_backup_base_dir`, `backup_plugin_dir`): backs up `dst` into `${PLUGIN_DATA}/backups/<YYYYMMDD-HHMMSS>/` using `shutil.copytree` and enforces that backups stay outside `dst` and `plugins/`.
- `scripts/tdq_setup_state.py:148-165,439-485,641-679`: stores `setup-state.json`, `setup-pending.flag`, and `secrets.env` in `${PLUGIN_DATA}`, isolated from plugin directory overwrites.
- `tools/patches/common_utils.py:45-82` (`sync_tree_inplace`): walks `src`, sets `stat.S_IWRITE`, copies via `shutil.copy2` (opens destination `'wb'`), and unlinks stale files without removing `dst` itself (`avoids WinError 32 on live plugin dir`).
- Windows PE locking risks:
  - `Get-Process` probe for `tdq|lsp|agy|antigravity` returned empty (`tdq-dispatch.exe` runs short-lived per hook invocation, not as a daemon).
  - `scripts/tdq_setup.py:162` explicitly notes Windows refuses in-place overwrite of running `~/.local/bin/agent-lsp.exe`; `scripts/tdq_setup.py:418-421` stops orphan brokers via `don_broker`, and `scripts/tdq_setup.py:236-247` uses `tempfile.mkstemp` + atomic replace.
  - If `shutil.copy2` overwrites `bin/tdq-dispatch.exe` while a hook/parent process still holds `tdq-dispatch.exe` mapped, Windows throws `PermissionError` (`WinError 5/32`). Safe updater should skip identical-hash `.exe` files or stage `.tmp` + `os.replace` (with `.old` rename fallback if needed).

### 3. Caveman Preservation & `--setupfully` Restart Chain

- `tools/install_agy_plugin.py:313-383` (`_apply_caveman_wrap`, `_handle_caveman`): probes `dst` (`probe_caveman(plugin_root=probe_root)`). When `probe.get("enabled")` is True (`line 374`), it automatically re-wraps `dst/mcp_config.json` (`reason="preserved_opt_in"`).
- `scripts/tdq_setup.py:2782-2827,2887-2917` (`_apply_caveman_addon`, `apply_setup_manifest`): with `setupfully=True`, wraps `mcp_config.json`, calls `enable_caveman(approve=True, ...)`, installs/verifies core + addons + companions, pins `~/.gemini/GEMINI.md`, and calls `_persist_awaiting_restart_state` (`scripts/tdq_setup.py:2869-2884`).
- `scripts/tdq_setup_state.py:379-408,542-578` (`compute_host_session_fingerprint`, `evaluate_restart_resume`): hashes `(platform, root_pid, create_time)` across `<=12` ancestor processes and sets `status="awaiting_restart"` + `setup-pending.flag`.
- `hooks/scripts/prompt_context.py:190-230` (`_evaluate_setup_setup_line`, `_emit_setup_hooks`): on subsequent turns (`source not in ("compact", "resume", "system")`), emits `remind_restart` while host fingerprint matches, then `run_verify` after Antigravity restarts (`current_fp != saved_fp`), chaining to `scripts/tdq_setup.py --post-restart-verify` (`scripts/tdq_setup.py:2946-2975`).

### 4. In-Chat Consent Trigger Pattern (`hooks/scripts/prompt_context.py:169-231`)

- `extract_setupfully_trigger(prompt)` (`lines 180-187`) chains: `_tach_prompt_thuc` -> `_has_prompt_grant_blockers` (rejects `NON_HUMAN_RE`, `QUOTED_SPEECH_RE`, `_GIT_GRANT_NEG_RE`) -> `_SETUPFULLY_Q_PHRASE_RE` (rejects questions) -> `_SETUPFULLY_QUOTED_RE` (rejects quoted text) -> `_SETUPFULLY_RE`.
- `_evaluate_setup_setup_line` (`lines 192-217`) restricts activation to `effective_new` human turns (`source not in ("compact", "resume", "system")`).
- This same strict guard pattern can gate an explicit update+setupfully phrase (`update tdq-workflow` / `cập nhật tdq-workflow`), paired with a `${PLUGIN_DATA}` snooze/dismiss record (version + cooldown timestamp) to prevent prompt spam when the user declines or defers an available update.
