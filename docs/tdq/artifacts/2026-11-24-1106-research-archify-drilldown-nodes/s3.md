## 1. Tại sao cơ chế băm hiện tại gây lãng phí token và tái vẽ hàng loạt?

Đối chiếu thực nghiệm trên `scripts/archify_artifacts.py` và `scripts/tdq_archify.py` cho thấy 3 nguyên nhân gốc gây đốt token và trễ phản hồi khi mở rộng lên `> 100` node / `>= 5` tầng:

1. **False-dirty ở mức toàn tệp (`_hash_file`):** `source_fingerprint` (`scripts/archify_artifacts.py:120-126`, `364-380`) băm toàn bộ nội dung file. Chỉ cần thêm 1 docstring ở cuối tệp hay dịch số dòng ở hàm khác trong cùng tệp dài (ví dụ `scripts/tdq_archify.py` dài `1,632` dòng), SHA-256 thay đổi khiến toàn bộ view gắn với tệp đó bị đánh dấu `stale`.
2. **Phạm vi theo dõi rộng (`5,804` tệp):** Khi `master.model.json` không khóa `source_paths`, `_derive_stable_source_paths` (`scripts/tdq_archify.py:747-748`) kéo toàn bộ `5,804` file vào `docs/architecture/manifest.json` (`1,222,506` bytes), làm bất kỳ thay đổi nhỏ nào ngoài luồng cũng kích hoạt rebuild.
3. **Tái render tuần tự + đóng gói nguyên khối:** Đo thực tế từ `docs/architecture/manifest.json` cho thấy mỗi lần `node archify.mjs finalize` mất trung bình `2,833 ms` cho 1 view (`overview` `2,748 ms`, `pipeline-lifecycle` `2,627 ms`, `search-and-archify` `2,712 ms`, `hooks-and-gates` `3,171 ms`, `runtime-verification` `2,883 ms`, `optimization-report` `2,857 ms`, cộng `master` `3,337 ms` = `20,335 ms` chỉ cho 6 view) và nhúng lặp `~276 KB` `htmlGzip` cho mỗi view.

## 2. Thiết kế Logic Node Registry & Cơ chế Hash 2 lớp chống False-Dirty

### 2.1. Cấu trúc kho mảnh phi tập trung (`docs/tdq/models/registry/`)

Thay vì nhồi mọi thứ vào 1 tệp `master.model.json` (`11,276` bytes) hoặc 1 JSON khổng lồ, tách thành **Kho Logic Node tái sử dụng** theo mô hình Content-Addressable + Sharded Registry:

- **`docs/tdq/models/registry/index.json`**: Bảng mục lục gọn (`node_id`, `title`, `layer`, `symbol_ref`, `ast_symbol_sha256`, `summary_sha256`, `sub_flow_slice_id`, `reused_by[]`, `evidence_kind`, `file_path`). Kích thước chỉ ~`150–250` bytes/node (`~25 KB` cho `120` nodes) → agent có thể kiểm tra trùng lặp và hit cache chỉ với `1` lần đọc mục lục hoặc chạy script Python (`0` LLM tokens).
- **`docs/tdq/models/registry/nodes/<node_id>.json`**: Hồ sơ chi tiết của đúng 1 Logic Node (mô tả tự nhiên tiếng Việt cho người đọc không chuyên lẫn dev, `io_contract`, `edge_cases[]`, `sub_flow` JSON rút gọn `<= 5` bước con hoặc trỏ `child_slice_id`, và danh sách `sources[{path, symbol, line, end_line}]`).
- **`docs/architecture/slices/<slice_id>.svg` & `.json`** (hoặc gộp manifest mảnh): Output SVG thuần (`~24–29 KB`/lát cắt thay vì `823 KB` full wrapper HTML). Toàn bộ portal `docs/architecture/index.html` chỉ nạp **1 bộ viewer runtime duy nhất**.

### 2.2. Chiến lược Hash 2 lớp (AST/Symbol Hash vs Span Binding)

Để một thay đổi không làm mất cache oan (false-dirty) nhưng vẫn giữ link dòng code chính xác:

| Lớp kiểm tra | Cách tính | Phản ứng khi thay đổi | Chi phí token LLM |
|---|---|---|---|
| **Lớp 1: `ast_symbol_sha256`** (Logic Digest) | Trích thân hàm/class bằng `ast` (Python) hoặc Tree-sitter / LSP symbol range, chuẩn hóa comment thuần định dạng & bỏ số dòng tuyệt đối rồi băm SHA-256 | **Không đổi** nếu chỉ thêm dòng trống hoặc sửa hàm hàng xóm → **CACHE HIT** | **`0` tokens** |
| **Lớp 2: `span_binding`** (Line Offset Check) | Nếu `ast_symbol_sha256` khớp nhưng `file_sha256` đổi (do file dịch dòng phía trên), script Python quét lại vị trí symbol để cập nhật `[line, end_line]` mới vào `node.json` | Cập nhật cơ học `line..end_line` và render lại link `sources` (không cần gọi LLM viết lại giải thích) | **`0` tokens** |
| **Lớp 3: `render_slice_sha256`** | Băm cấu trúc đồ thị (`nodes` + `edges` + `labels`) của riêng lát cắt `<= 5` node | Chỉ gọi `archify finalize` đúng lát cắt đổi cấu trúc; nếu chỉ sửa văn bản giải thích trong modal → không cần chạy Node SVG engine | **`0` ms Node finalize** nếu chỉ đổi prose |

## 3. Incremental Layers 1–2 + Lazy Depth Layers 3–5+ & Ca biên bắt buộc

### 3.1. Mô hình kết hợp theo chiều sâu (Depth-Tiered Hydration)

1. **Tầng 1–2 (Eager Backbone — Incremental Dirty-Only):** Luồng tổng hệ thống và các quy trình nghiệp vụ cốt lõi (mỗi lát cắt `3–5` node). Đồng bộ mỗi khi `sync-master`, nhưng script Python chỉ đánh dấu `dirty_set` gồm đúng những node có `ast_symbol_sha256` thay đổi (`O(D)`).
2. **Tầng 3–5+ (Lazy Depth — On-Demand Hydration):** Chi tiết vi mô (ví dụ mini-flowchart *cách ghi Remember Token vào Cookie/HttpOnly hay Keychain*, giải mã JWT, xử lý rate limit) **chỉ sinh lần đầu** khi có request TDQ chạm tới hoặc người dùng/agent yêu cầu đào sâu luồng đó. Ngay khi sinh xong, node được lưu vào Registry kèm `reused_by[]` để **mọi request và flow sau tái sử dụng vĩnh viễn** chừng nào `ast_symbol_sha256` còn sạch.

### 3.2. Xử lý 3 ca biên kỹ thuật cốt lõi

- **Chống chu trình đệ quy (`cycle` / `chu trình`, ví dụ `A -> B -> A` hoặc `Refresh Token -> Retry Auth -> Refresh Token`):**
  Viewer duy trì ngăn xếp đường dẫn `visited_stack = [node_root, ..., current_node]` trên breadcrumb. Khi kiểm tra biên `sub_flow` (cả lúc kiểm định tĩnh bằng Python lẫn lúc click trên UI): nếu `target_node_id` đã nằm trong `visited_stack` (hoặc `depth >= max_depth` mặc định `6`), hệ thống không mở thêm tầng vô hạn mà hiển thị **Thẻ neo chu trình** (`↺ Quay về bước "<label>" ở tầng k`) kèm nút nhảy trực tiếp về vị trí đó trên breadcrumb.
- **Tách biệt rạch ròi `planned` (Spec) và `working-tree`/`committed` (Code thật):**
  Trong pha Spec, agent có thể tạo `LogicNode` dự kiến mang `"evidence_kind": "planned"`, `"ast_symbol_sha256": null`, `"symbol_ref": "planned:auth.remember_login"` lưu ở vùng nháp Spec (`docs/tdq/artifacts/<slug>/planned-nodes.json`) để hiển thị huy hiệu `[Dự kiến / Chưa có code]` trên sơ đồ Spec Before/After. Tuyệt đối **không trộn** node `planned` vào Master Registry chính thức cho tới khi pha Implement + QC xác minh file nguồn thật và nâng cấp lên `working-tree` / `committed` kèm `path:line` thực tế.
- **Khắc phục lỗi CORS khi mở cục bộ bằng `file://`:**
  Kiểm chứng tại `scripts/archify_delivery.py:310-332` cho thấy `tdq_archify.py open` mở trực tiếp URI `file:///` bằng `os.startfile`, còn `scripts/tdq_archify.py:1493-1632` chưa có lệnh `serve`. Trình duyệt hiện đại chặn `fetch('./slices/x.json')` từ trang `file:///` do chính sách CORS `null` origin. Vì vậy kiến trúc phải hỗ trợ **2 chế độ đóng gói**:
  1. **Master Portal (`docs/architecture/`):** Phát hành dưới dạng multi-file nhẹ phục vụ qua **HTTP thật** (Tailscale Serve hiện có hoặc lệnh cục bộ `tdq_archify.py serve` khởi chạy HTTP tĩnh tạm thời trên `127.0.0.1` trước khi mở trình duyệt), cộng thêm fallback nạp `<script src="registry-bundle.js">` (gán `window.__TDQ_REGISTRY__` thuần không cần `fetch`, hoạt động được cả trên `file://` mà không lặp lại runtime `820 KB` của từng diagram).
  2. **Spec / Report HTML (`docs/tdq/reports/<slug>.html`):** Giữ **1 file HTML tự chứa** để gửi qua Tailscale hoặc mở offline 1 click, nhưng bỏ bản sao `htmlGzip` dư thừa cho các node giải thích chi tiết (chỉ nhúng dictionary node + SVG `~25 KB`/lát cắt khi số tầng `<= 4`).

## 4. Ước lượng định lượng Token & Thời gian Agent (`H3`)

### Bối cảnh benchmark tham chiếu (đo thực tế + ngoại suy có kiểm soát)

- **Số liệu đo nền (`Verified` trong repo):**
  - 6 file JSON mô hình view hiện tại (`docs/tdq/models/*.json` trừ `master.model.json`) có tổng kích thước `29,502` bytes (`~4,917` bytes/view, `~1,230` tokens YAML/JSON mỗi view).
  - Mỗi lần gọi `node archify.mjs finalize` trung bình mất `2,833 ms` cho 1 view (`docs/architecture/manifest.json`), `explainer` mất `1,849–2,197 ms`.

## 5. Kết luận thẩm định `H3` (Verified nền + Inferred định lượng)

- **Phần nền tảng (`Verified`):** Cơ chế `_hash_file` (`scripts/archify_artifacts.py:120-126`) và `5,804`-file walk (`docs/architecture/manifest.json`) chắc chắn gây false-dirty; thời gian `finalize` đo được trên máy thật là `~2.83s`/view nên tái render `O(N)` không khả thi ở ngưỡng `> 100` node; `open_artifact` dùng `file://` đòi hỏi fallback JS bundle hoặc HTTP server.
